## Intent

**Problem:** Typing on a phone is the slowest part of Echo's messaging story, and it excludes the low-vision users the app is built for. The chat composer is text-only; nothing in the app can reach the microphone.

**Approach:** Add a WhatsApp-style mic to the chat composer — press and hold, speak, release. Slide up locks hands-free recording, slide left cancels. Audio is captured as 16 kHz Float32 PCM by `react-native-audio-api` and transcribed on-device by executorch's `useSpeechToText` (Whisper tiny.en). The transcript lands in the draft field for review, not straight onto the mesh. Fully offline once the model is cached.

## Boundaries & Constraints

**Always:**
- This adds a **native dependency**, so it needs a prebuild and a new dev-client APK. Land it on its own branch, announce it, and log the toolchain outcome in `SETUP.md` per `SETUP.md:107` and `:269`.
- Gesture maths, waveform framing and draft merging stay **pure** in `src/utils/dictation.ts` — `import type` only, no React/Expo/executorch — and unit-tested per the `src/utils/ocr.ts` convention.
- Guard `transcribe()` on `isReady && !isGenerating` behind a `useRef` latch, and gate loading with `preventLoad`, exactly as `useReadText.ts:40,56,65` does. Both throws (`ModuleNotLoaded`, `ModelGenerating`) are live hazards.
- Waveform contract is unforgiving: **16 kHz, mono, Float32 in −1.0…1.0**. Below `kMinChunkSamples` (16000 = 1 s) there is nothing to transcribe; cap a take at `kMaxSamples` (464000 = 29 s).
- **Disable `useShake` while recording** (`useShake(handler, !recording)`). Raising the phone to your mouth crosses the 1.7 g threshold, and the untaken branch calls `revertLastCoin` with no confirmation.
- Every gesture needs a tappable equivalent (the project rule in `useShake.ts`'s header). Lock and cancel must both be reachable by tap.
- Reuse existing tokens and components — `useTheme`, `radius`, `TOUCH_MIN`, `Display`/`Mono`, the `s.rbtn` shape. Recording state uses `c.direct`; `c.coin` is money-only and must not encode state.
- `accessibilityRole`, a sentence-style `accessibilityLabel` and `accessibilityState` on every control; `hitSlop` to reach 48 dp rather than growing the composer row.

**Ask First:**
- Any change beyond adding `react-native-audio-api` to `package.json`/`app.json` — extra npm deps, a second model, or a VAD download.
- **If `react-native-audio-api` will not build.** Issue #1012 reports `:react-native-audio-api:downloadPrebuiltBinaries` failing on Windows (`execvpe(/bin/bash)`) plus an RN 0.85+ JNI break, closed with no upstream fix. If a `scripts/` postinstall patch in the `fix-nearby-prefab.js` mould does not clear it, **HALT** — do not swap engines unilaterally.
- Auto-sending the transcript instead of staging it in the draft.

**Never:**
- No streaming transcription, no `stream()`/`streamInsert()`, no VAD model. Batch `transcribe()` on release only.
- No Moonshine — it does not exist in executorch 0.9.2; Whisper is the only architecture the native runner supports.
- No voice-note attachment: the recording is transcribed and discarded, never sent as audio.
- No hand-edited `AndroidManifest.xml` — `android/` is gitignored and regenerated by prebuild.
- No changes to the mesh store, transport, or any other screen.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|---|---|---|---|
| Happy path | Model ready, hold ≥1 s, speak, release | Tick on press; on release transcribe, append text to `draft` with a single separating space; success haptic | N/A |
| Too short | Released with <16000 samples | Discard, never call `transcribe()`; fail haptic; note "Hold to talk" | N/A |
| Slide to lock | `dy` past lock threshold | Latches recording; release no longer stops it; Stop and Cancel become tappable | N/A |
| Slide to cancel | `dx` past cancel threshold, or Cancel tapped | Recording aborted, buffers dropped, no transcription; note "Cancelled"; draft untouched | N/A |
| Hit the ceiling | Take reaches 464000 samples | Auto-stops at 29 s and transcribes what it has | N/A |
| Model still loading | `isReady === false` | Mic disabled, labelled "Loading model NN%" from `downloadProgress` | N/A |
| Mic permission refused | `requestRecordingPermissions() !== 'Granted'` | No recording starts; note explaining why | Permanently denied → note directing the user to system settings |
| Empty or failed transcript | `transcribe` rejects, or `text` is blank | Fail haptic; note "Didn't catch that"; draft unchanged | Caught; state reset so the mic re-arms |
| Model fails to load | `error` set on the hook | Mic disabled, note "Dictation unavailable", retry remounts the hook | Never show "Loading model 0%" while `error` is set |
| Left mid-take | Back pressed / screen unmounts while recording | Recorder stopped and buffers freed; no setState or haptic after unmount | Mounted ref suppresses late feedback |

## Spec Change Log

### Iteration 1 — review findings (Blind Hunter + Edge Case Hunter)

**Triggering finding (intent gap, human-resolved):** the spec required "gate loading with `preventLoad`" but never said *what* gates it. `ChatScreen.tsx:93` called `useDictation({ onAutoStop })` with no `enabled`, so `preventLoad` was permanently `false` and **opening any chat started a 224 MB download and pulled Whisper into RAM** — on any connection. `SPEECH_MODEL` was left unreferenced, so the documented "pre-download over wifi" path did not exist. Human chose opt-in preload, mirroring the 398 MB `LANGUAGE_MODEL`.

**Second triggering finding (bad spec):** the original Task 7 and Design Notes prescribed swapping send↔mic on `draft.trim()`. Implemented faithfully, this made dictation **single-shot** — the moment a transcript landed the draft was non-empty, the mic disappeared, and `mergeDraft`'s append path (unit-tested at `test/dictation.test.ts`) became unreachable. Worst for the blind user the feature targets. Human chose a permanently visible mic with send appearing alongside.

**Known-bad state avoided:** a build whose headline accessibility feature silently costs 224 MB on first chat open and can only ever be used once per message.

**KEEP (must survive re-derivation):**
- The verified `react-native-audio-api@0.13.2` contract: `Result<T>` is **returned, not thrown**; `AudioManager` is a default-exported singleton; `getChannelData(0)`'s buffer is **recycled**, so `slice()` is load-bearing.
- Whisper's native constants pinned in `utils/dictation.ts` and asserted in the tests: 16000 Hz, `kMinChunkSamples` 16000, `kMaxSamples` 464000.
- `utils/dictation.ts` with zero runtime imports, and its 13 tests.
- `useShake(handler, !recording)` — the accelerometer/`revertLastCoin` clash is real.
- The Windows Gradle fix (`scripts/fix-audio-api-bash-path.js`) and the deliberate `app.json` plugin config. These are proven by a successful `assembleDebug` and are unrelated to both findings.

**Amendments (new tasks below, unchecked):** gate loading on an opt-in download marker; keep the mic permanently visible; correct the inverted permission mapping; close the audio-session and orphaned-recorder leaks; fix the `cancel()` re-entrancy window; stop discarding captured audio silently; reset the shake cooldown on re-enable; verify the delivered sample rate.

## Design Notes

The mic is **permanently visible**; the send arrow appears beside it only when the draft has text. An earlier revision swapped the two in one slot to save width — that made dictation single-shot, because a landed transcript fills the draft and would remove the very control that produced it. The cost is real: with four controls the text field drops to roughly 136 dp on a 360 dp screen. Re-dictation and correction matter more than those pixels.

Loading is opt-in. At 224 MB Whisper sits closer to the 398 MB LLM (`auto={false}`) than to the 50 MB vision models (`auto={true}`), so it must never download as a side effect of opening a chat. A marker file records the opt-in, mirroring `features/vault/api/identity.ts` — `expo-file-system` is already in the build, so this costs no new dependency and no new APK.

Gesture phase is pure, so it is testable without a device:

```ts
export const gesturePhase = (
  { dx, dy }: { dx: number; dy: number },
  locked: boolean
): 'recording' | 'armed-lock' | 'armed-cancel' =>
  dx < CANCEL_DX ? 'armed-cancel'
  : !locked && dy < LOCK_DY ? 'armed-lock'
  : 'recording';
```

Whisper pads every input to a fixed 30 s window, so a 2 s utterance costs the same encode as a 25 s one (~277 ms encode on a Galaxy S24, ~28 ms per decoded token). Latency is therefore near-constant and dominated by transcript length — worth knowing before optimising the wrong thing.
