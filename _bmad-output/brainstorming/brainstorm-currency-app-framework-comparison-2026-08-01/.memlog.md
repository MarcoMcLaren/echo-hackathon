- (technique by coach) started First Principles Thinking
- (insight by coach) Bedrock: a currency is only three things - a unit, a record of who holds what, and rules for moving units
- (insight by coach) Bedrock: a transfer is reduce A, increase B, exactly once, with both parties convinced. Without a server, exactly-once is the only genuinely hard part
- (insight by coach) Bedrock: a phone is a bag of radios, sensors, a screen, a secure chip and a battery. Nothing more
- (insight by coach) Bedrock: a framework comparison is only meaningful if both builds do identical work
- (idea by coach) Rebuild: the atom is not a balance, it is a signed note - a bearer token with a value and a chain of endorsements. Transfer = append your signature and hand it over. No global ledger
- (idea by coach) Rebuild: double-spend is not prevented, it is detected - two conflicting endorsements on one note provably identify the forger by their own signature
- (idea by coach) Rebuild: detection needs the branches to eventually meet, so devices gossip note histories over every radio they have - the mesh is not a feature, it IS the fraud detector
- (idea by coach) Rebuild: how much do I have becomes which notes am I holding - the wallet UI is a set of objects, not a number, which is far richer to render and animate
- (idea by coach) Rebuild: notes split and merge, so the UI needs a tactile split gesture - drag a note in half
- (idea by coach) Rebuild: a note is just bytes, so ANY channel that moves bytes is a transfer method - the device capability list becomes an exhaustive enumeration of byte channels
- (idea by coach) Rebuild: the minimum viable channel is roughly 200 bytes one-way, which is exactly why QR, chirp, SMS and BLE advert all qualify - and tells you which exotic channels are worth building
- (insight by coach) Rebuild: trust bootstraps from a physical meeting, so every pairing method is really a key exchange plus a proximity proof - capabilities differ only in how convincingly they prove proximity
- (idea by coach) Rebuild: rank every transfer method on two axes - bytes/sec and strength-of-proximity-proof - producing a map of which channels are for payment and which are for pairing
- (insight by coach) Rebuild: the comparison bedrock is how much native code you had to write and how well the result ran - the honest metric is glue-LOC times runtime-perf, per capability

- (technique by coach) started Five Whys - chain on 'why build the same currency app twice'
- (insight by coach) Why 1 - why build it twice? To compare React Native and Flutter fairly
- (insight by coach) Why 2 - why a currency app specifically? Because it forces breadth: radios, sensors, secure hardware, background work and heavy list rendering in one product
- (insight by coach) Why 3 - why does breadth matter? Because both frameworks are equally fine at simple apps; they only diverge at the native boundary and under load
- (insight by coach) Why 4 - why care where they diverge? Because the real decision is not which is prettier, it is which stays tractable when we need something the ecosystem has not wrapped yet
- (insight by coach) Why 5 - ROOT CAUSE: the cost of a mobile framework is paid entirely in the long tail - the capability with no plugin, the background job that must survive Doze, the one 120fps screen. We are really evaluating ESCAPE HATCHES, not frameworks
- (idea by coach) Therefore: deliberately weight the app toward capabilities with NO mature plugin in either ecosystem - UWB, MST, ultrasonic, satellite, flashlight VLC - because that is where the answer lives
- (idea by coach) Therefore: measure time-to-first-working-bridge for a capability neither dev has done before, with a stopwatch, honestly
- (idea by coach) Therefore: the deliverable is not a winner, it is a decision table - if your product needs X, pick Y

- (insight by coach) SYNTHESIS - the single reframe that reorganizes everything: this is not a currency app that happens to compare frameworks, it is a FRAMEWORK BENCHMARK wearing a currency app as a costume. Every design choice should be judged by what it reveals about RN vs Flutter
- (insight by coach) SYNTHESIS - the bearer-note model (First Principles) quietly solves the whole transfer-method sprawl (Yes And): if a note is ~200 bytes, every device capability is just another byte channel, and the sprawl becomes a single uniform abstraction with N drivers behind it
- (insight by coach) SYNTHESIS - three ideas are one idea in three hats: the bump-derived key, UWB ranging, and ultrasonic time-of-arrival are all PROXIMITY PROOFS. Unify them behind one interface and the app gains a security model instead of a pile of gimmicks
- (insight by coach) SYNTHESIS - the gossip mesh (First Principles) and the offline double-spend fraudster (Role Playing) are the same mechanism seen from both sides: the relay network exists to make forgery eventually visible, not to move money faster
- (insight by coach) SYNTHESIS - the Five Whys root cause plus the reverse-brainstorm insight combine into the sharpest methodology available: write the native code ONCE per platform, bridge it TWICE, and stopwatch the bridge. That isolates the actual variable and is the only honest measurement in the whole plan
- (insight by coach) SYNTHESIS - the wildcard with the most upside: notes-as-objects instead of a balance number. It makes the UI a physical, animatable, splittable thing - which is precisely the workload that separates Impeller from Fabric, so the data model and the benchmark reinforce each other
- (insight by coach) DIRECTION - recommended shape: one shared spec, one shared E2E suite, three bulletproof hero channels (NFC, animated-QR, BLE mesh) plus labelled novelty channels, a live in-app telemetry screen, and a decision-table deliverable rather than a winner
- (direction by user) HARD CONSTRAINT: the Flutter project and the React Native project must be COMPLETELY SEGREGATED - no shared code, no shared build, no shared dependency tree
- (insight by coach) TENSION: full segregation collides with the session's sharpest methodology finding (write native code once per platform, bridge it twice). Resolution: segregate IMPLEMENTATIONS, share CONTRACTS. The Kotlin/Swift native code is duplicated as byte-identical COPIES into each project (verified by checksum in CI), never as a shared Gradle module or pod. Same isolation of the variable, zero coupling
- (insight by coach) Segregation boundary - what is duplicated: source, build config, dependency tree, CI pipeline, app id, signing. What is shared as documents not code: the wire-format spec, the shared E2E suite (Maestro/Appium runs against both), the telemetry schema, the Figma, the threat model
- (idea by Segregation forces distinct applicationId/bundleId, which means BOTH apps install on ONE phone simultaneously - unlocking interleaved back-to-back benchmarking on identical hardware and thermal state, which the reverse-brainstorm demanded) 
- (idea by Killer consequence of segregation: the RN app can pay the FLUTTER app. Cross-framework transfer becomes the headline demo AND the strictest possible conformance test - it proves both builds implement the same wire format rather than merely looking alike) 
- (idea by Because both apps coexist on one device, they need distinct BLE service UUIDs and NFC AIDs to avoid intercepting each other - so the wire spec must define a framework-agnostic app identity separate from the transport identifier) 
- (idea by Segregation makes the glue-LOC metric trivially auditable - cloc each repo, subtract the checksum-identical native files, and what remains IS the bridge cost per framework) 
- (idea by Repo shape: currency-rn/ and currency-flutter/ as fully independent projects (separate repos or sibling top-level dirs with no parent build), plus a third spec/ holding only documents and the shared test suite - no build system spans the boundary) 
- (decision by user) ADOPTED: segregate implementations, share contracts. Native Kotlin/Swift duplicated as byte-identical checksum-verified copies into each project; only documents (wire spec, E2E suite, telemetry schema, Figma, threat model) cross the boundary. No build system spans currency-rn/ and currency-flutter/
