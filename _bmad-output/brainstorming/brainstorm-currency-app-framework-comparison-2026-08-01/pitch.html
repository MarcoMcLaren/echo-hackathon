The hook

Money that moves phone‑to‑phone with nothing in the middle — built twice.

A peer-to-peer currency that transfers between devices with no cell, no wifi, no server and no accounts. We shipped it once in React Native and once in Flutter as a controlled experiment — same spec, same tests, same phone.

01

The real thesis

We are not comparing which framework is prettier. We are measuring escape hatches.

Both frameworks are equally fine at simple apps. They diverge only at the native boundary and under load. The cost of a mobile framework is paid entirely in the long tail — the capability with no plugin, the background job that must survive Doze, the one 120 fps screen.

  • So the app is deliberately weighted toward capabilities with no mature plugin in either ecosystem — that is where the answer lives.
  • UWB ranging. Ultrasonic data. Satellite messaging. Flashlight visible-light comms.
  • We stopwatch time-to-first-working-bridge for capabilities neither developer has attempted before. Honestly.

02

How it works, in four beats

BEAT 01

Bearer notes, not balances

The atom is a signed note of roughly 200 bytes carrying a value and a chain of endorsements. Transfer = append your signature and hand it over. No global ledger. Your wallet is a set of objects you can split and merge, not a number.

BEAT 02

Any channel that moves bytes

A note is just bytes, so every transport is the same abstraction with a different driver behind it. The minimum viable channel is ~200 bytes, one-way — which is exactly why QR, chirp, SMS and a BLE advert all qualify.

BEAT 03

Double-spend is detected, not prevented

Two conflicting endorsements on one note provably identify the forger by their own signature. Devices gossip note histories over every radio they have — so the mesh is not a feature, the mesh IS the fraud detector.

BEAT 04

Keys never leave the hardware

Signing lives in the secure enclave — StrongBox on Android, Secure Enclave on iOS — which also makes keystore bridging part of the comparison. Trust bootstraps from a physical meeting: every pairing is a key exchange plus a proximity proof.

03

The channel spread

Three channels must be bulletproof. The rest are demo-grade novelties, and we label them as such.

Hero channel — must never fail Novelty — demo-grade, labelled

NFC tap Hero

Host Card Emulation, phone to phone. A note jumps devices on contact. Also works written to a physical tag — a cash drop on a table.

Animated QR Hero

A rotating series of fountain-coded frames streamed optically at ~10 fps. No handshake — it completes when enough frames land. Works phone-to-screen, so you can pay over a video call.

BLE mesh relay Hero

Phones forward signed transfers for strangers with TTL and dedupe, so currency hops across a festival. Micro-transfers can ride in the advertisement packet itself — broadcast, no connection.

Ultrasonic chirp Novelty

The payload goes out as sound the mic decodes — in the dark, or with the camera busy. One payer pays a whole room at once. Chirps carry a nonce and a short expiry so a recording cannot be replayed.

Bump to pay Novelty

Both accelerometers spike within 50 ms. The bump waveform itself becomes the jointly-derived session secret — never self-reported, so it cannot be spoofed. The most accessible transfer method there is: no aiming, no hunting for a code.

UWB ranging Novelty

Pins the counterparty to ~10 cm. Physical presence becomes a settlement rule, not a courtesy.

SMS on 2G Novelty

The transfer encodes as a base64 payload in a plain text message. No data connection required at all.

Satellite Novelty

Carries an emergency transfer out of a dead zone on satellite-messaging hardware. No tower, no cloud.

Flashlight VLC Novelty

The torch strobes the payload as visible light. Pay across a room, or through a window.

04

Why the experiment is honest

A framework comparison is only meaningful if both builds do identical work. So we engineered the framework into being the only variable.

// the methodology that isolates the variable
native capability  →  written ONCE per platform (Kotlin / Swift)
                    →  bridged TWICE (RN  |  Flutter)
                    →  stopwatched  // the bridge is the measurement
One shared spec, one shared E2E suiteBoth builds must pass the same wire-format spec and the same end-to-end tests, identically. Contracts are shared as documents — never as code.
Completely segregated projectsNo shared code, no shared build, no shared dependency tree. Native sources are duplicated as byte-identical, checksum-verified copies — same isolation of the variable, zero coupling.
Both apps on one phone, interleavedSegregation forces distinct app identities, so both install simultaneously and run back-to-back on identical hardware and identical thermal state.
A null-app baseline for calibrationAn empty scroll list ships in both builds, so we can tell a framework difference from our own code.
Release builds, cold, after rebootEvery timing comes from a release build launched cold following a reboot. Hot reload never touches a number we report.
No home-field advantageA deliberately custom design — neither Material nor Cupertino — so neither framework gets to win on its own defaults. Bridge cost is audited by subtracting the checksum-identical native files.

06

What we are honest about

Play currency, not real money

A hard, loud, this-is-not-real-money boundary. The demo currency is visually unmistakable as fake, which keeps the project clear of e-money licensing and app-store rejection.

A security demonstrator, not a bank

Someone will call it a security toy, so we say it first. The threat model is a first-class screen inside the app — and a fraud-demo button deliberately double-spends on stage to show detection firing.

iOS forbids what Android allows

NFC HCE, background BLE and raw wifi are restricted on one platform and open on the other. That gap is a headline finding, not a blocker.
