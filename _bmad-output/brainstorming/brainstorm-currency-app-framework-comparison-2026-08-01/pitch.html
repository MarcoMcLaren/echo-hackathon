Bearer  /  offline currency, built twice
React Native Flutter Controlled experiment

The hook

Money that moves phone‑to‑phone with nothing in the middle — built twice.

A peer-to-peer currency that transfers between devices with no cell, no wifi, no server and no accounts. We shipped it once in React Native and once in Flutter as a controlled experiment — same spec, same tests, same hardware.

01

The real thesis

We are not comparing which framework is prettier. We are measuring escape hatches.

Both frameworks are equally fine at simple apps. They diverge only at the native boundary and under load. The cost of a mobile framework is paid entirely in the long tail — the capability with no plugin, the background job that must survive Doze, the one 120 fps screen.

  • So the product is deliberately shaped around capabilities with no mature plugin in either ecosystem — every transport is a driver behind one interface, and that is where the answer lives.
  • One day buys the spine and one channel, measured properly. The exotic drivers are a named continuation, not a claim — and this page marks which is which.

The killer demo · two beats

Flip one switch, and the React Native phone pays the Flutter phone.

Four phones on stage — two React Native, two Flutter. Airplane mode on. One phone renders a QR code, the other scans it, and the note moves. The whole 96-byte tip fits in a single static QR: no frame streaming, no fountain codes, nothing to go wrong.

Why one toggleNotes are framework-blind by design; only discovery filters on a framework tag. Turning that filter off converts an ordinary feature into the headline — and if the switch fails on stage, beat one still works and the story survives.
Why optical, not NFCA tap is invisible to an audience — a QR on a screen is not. So we split the two: NFC is the product channel, optical is the demo channel. Crossing frameworks proves both builds implement the same wire format rather than merely looking alike.
The counterintuitive finding

We deleted our own crown jewel to see what survived — and removing NFC made the iOS story dramatically better, because host card emulation was the single biggest iOS blocker. The system is now NFC-optional from day one: NFC is a driver, not a foundation.

02

How it works, in four beats

BEAT 01

Bearer notes, not balances

The atom is a note: a fixed 96-byte tip — id, value, holder key, signature — plus optional history. Transfer = append your signature and hand it over. No global ledger. Wallets start preloaded; on the day the signing key is software, with a visible TODO where the enclave goes.

BEAT 02

One-way, fire and forget

A QR code cannot acknowledge anything — so the entire protocol works with no ACK at all. That forces every note to be a complete, self-contained, independently verifiable object. It is the highest-leverage constraint in the project.

BEAT 03

Three wire profiles

TINY 31 bytes, SMALL 255 bytes, FULL unbounded. Every channel declares what it can carry — so adding a capability is writing a driver, not redesigning the protocol. The 96-byte tip sits in SMALL, which is why one static QR is enough.

BEAT 04

Double-spend is detected, not prevented

Two conflicting endorsements provably identify the forger by their own signature, and the branch is poisoned rather than reassigned. A fraud button double-spends on purpose and detection fires live. Gossip across a multi-hop mesh is how that scales — on stage it is two phones, and we say so.

03

The channel spread

One channel ships on the day. Every other channel is a driver behind the same interface — which is exactly the point, and exactly why we can say honestly which ones we did not write.

Ships on stage Next driver up Designed, not built

Static QR Ships Demo channel

The 96-byte tip fits in one code. Render it, scan it, the note moves — no handshake, no streaming, no fountain codes. Animated QR is the stretch upgrade for the FULL profile carrying history, not the foundation.

NFC tap Next driver Product channel

Maximal proximity proof, and the only channel that works with the screen off and the app backgrounded — which is why iOS restricting host card emulation is the most consequential platform gap we found.

Flashlight VLC Next driver

The torch strobes the payload as visible light; the camera samples luminance. No plugin exists anywhere, yet it is trivially cheap — the best exotic channel per unit of wow, and it scores on the metric that matters.

BLE mesh relay Next driver

Phones forward signed notes for strangers with TTL and dedupe. The one we most want next, because background execution reliability is precisely the long-tail cost that decides a framework.

Bump · UWB Designed, not built

The pairing half of the architecture: a jointly-derived bump secret, or UWB pinning a counterparty to ~10 cm. Specified, scored, and left unwritten — UWB hardware is rare and neither fits a day.

Ultrasonic · SMS · Satellite · MST Cut

Ultrasonic DSP is a real build. SMS is Android-only — iOS forbids programmatic send. Satellite has no third-party API on either platform, and MST hardware is dead. Slides, not features, and we say so.

04

The third dimension: agentic integration

On-device LLM, tool calling, background agent loops — possibly the most decisive dimension of all, because the two frameworks have structural advantages pointing in opposite directions.

FlutterFirst-class FFI and first-class isolates. The structural edge is in the binding.
→  ←
React NativeThe agent SDKs and the MCP SDK are TypeScript-first. The structural edge is in the ecosystem.

The agent is not a chatbot. It is a trust oracle for the mesh.

  • It decides which peer to relay a note to.
  • It explains in plain language why a transfer is stuck.
  • It narrates a detected double-spend as a story instead of a hash comparison.

Agents propose; deterministic code executes, behind a biometric gate, and the model never touches unverified bytes. That is the safety boundary — and the same line makes the executing half unit-testable. It is the role we designed for; the day only buys us the Tier A number.

The three-tier test — one tier ran
  1. aRan on the day. Remote GPU, no native code on either side — isolates pure UI streaming. One real, comparable number.
  2. bEach framework's blessed runtime — ecosystem convenience. About a day per side. Not built.
  3. cThe same model via the same llama.cpp both sides, Dart FFI versus a Nitro module — pure binding cost. About a week. Not built.

Tier A is explicitly online, and the currency itself never needs a network. B and C are the post-hackathon continuation — but the design matters now, because it kills the confound that would have quietly invalidated the dimension: ExecuTorch versus llama.cpp compares runtimes, not frameworks.

05

Why the experiment is honest

A framework comparison is only meaningful if both builds do identical work. So we engineered the framework into being the only variable.

Segregation is also the time strategy

Total separation is not only what makes the comparison honest — it is what makes it fit in one day. Two devs, one frozen spec, two independent projects, no shared build, no merge conflicts. Perfect parallelism is the only reason building twice was ever feasible.

// the rule every capability follows
native capability  →  written ONCE per platform (Kotlin / Swift)
                    →  bridged TWICE (RN  |  Flutter)
                    →  stopwatched  // the bridge is the measurement

Day one writes no native code at all — a static QR needs none. This is the rule the drivers follow the moment one is written.

One frozen spec, read by both devsThe wire format is prose, byte-by-byte, frozen before either app starts. Contracts cross the boundary as documents — never as code.
A neutral arbiter, not a handshakeHand-authored test vectors, committed before either app exists and generated by neither. When the two builds disagree the vectors settle it — proving they implement the same spec, not the same bug.
Completely segregated projectsNo shared code, build or dependency tree — which is also what makes bridge cost auditable the moment native drivers exist: subtract the byte-identical files.
Both apps on one phone, interleavedSegregation forces distinct app identities, so both install simultaneously and run back-to-back on identical hardware and identical thermal state.
Cold, and no home-field advantageEvery timing comes from a release build launched cold after a reboot, and the UI is deliberately neither Material nor Cupertino.

07

What we are honest about

We scored every channel on two axes — throughput and strength of proximity proof — and no channel is strong on both. So every real transfer is a pair: a pairing channel to establish trust, a payment channel to carry the bytes. That is the architecture, not a hand-wave.

Play currency, not real money

A hard, loud, this-is-not-real-money boundary. The demo currency is visually unmistakable as fake, which keeps the project clear of e-money licensing and app-store rejection.

A security demonstrator, not a bank

Someone will call it a security toy, so we say it first. The threat model is a first-class screen inside the app — and a fraud-demo button deliberately double-spends on stage to show detection firing.

iOS forbids what Android allows

NFC HCE, background BLE and raw wifi are restricted on one platform and open on the other. That gap is a headline finding, not a blocker.

What we did not build

Agentic Tiers B and C. Ultrasonic, UWB, satellite, SMS. Hardware-backed keys — the day ships a software key with a visible TODO. Sensor-based minting — wallets start preloaded. Multi-hop relay — two phones, labelled as two phones. Named here so you do not have to find them.

The loaded die, disclosed

Our React Native base already had a working on-device LLM and a working mesh transport. React Native starts this experiment with a head start. So every timing is measured from clean scaffolds in both frameworks — and the head start is printed in the results rather than hidden in them.
