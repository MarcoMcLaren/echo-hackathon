- (constraint) KEYSTONE: the transfer protocol is ONE-WAY, fire-and-forget. QR and broadcast channels cannot ACK, so a transferred note must be a complete, self-contained, independently verifiable object
- (constraint) Notes are framework-blind. Framework tagging lives in the transport (BLE service UUID, NFC AID), never in the note - this is what makes cross-framework payment work
- (constraint) Airplane mode is the acceptance criterion for every channel, not a final test
- (constraint) All comparison timings measured from CLEAN SCAFFOLDS, never from the echo-hackathon base repo, which already ships expo-nearby-connections and react-native-executorch

- (constraint) Time budget approximately 8 hours, 2 devs (one per framework) plus 1 floater
- (decision) v0 note is UNSIGNED - id, value, holder. Signatures deferred behind the version byte. Double-spend detection still works via a seen-id set. Consequence: the 'forger proven by their own signature' claim must be dropped from the pitch unless ed25519 lands
- (decision) Four channels as four DRIVERS behind one interface: static QR (FULL), Nearby Connections (FULL), multi-hop relay (app-layer, over Nearby), NFC tag (SMALL)
- (decision) NFC ships TAG-BASED, not Host Card Emulation. HCE needs a native Android service plus AID registration in both frameworks and Android Beam was removed in Android 10. Tag-based is cheaper and makes the bearer-note story physical
- (decision) BLE uses Google Nearby Connections on both sides (expo-nearby-connections / nearby_connections), not raw GATT. Raw BLE peripheral advertising is the weak spot in both ecosystems; Nearby wraps the SAME native API on both sides, which is a fairer binding comparison
- (decision) Bluetooth mesh is APP-LAYER multi-hop relay (TTL + dedupe + forward) over the Nearby transport, not SIG Bluetooth Mesh. Pure TS/Dart, no native - a clean language-level comparison
- (decision) No database (notes persist as a JSON blob), no navigation library (three views behind a state enum), no in-app telemetry screen (captured externally via adb)
- (decision) Telemetry captured externally: adb shell am start -W for cold start, ls for APK size, dumpsys gfxinfo for frame times, dumpsys meminfo for memory. Zero app code and no observer effect
- (decision) Static QR only. A 96-byte tip fits one static code; animated QR and fountain coding are a stretch, not a foundation

- (decision) v0 note layout fixed at 42 bytes: ver(1) flags(1) note_id(16) value(4 u32BE) holder(16) lamport(4 u32BE). All fixed-width, big-endian, no length prefixes - canonical form is trivial and there is no Dart-vs-JS serialization mismatch to debug
- (decision) Transmit base64url of the 42 bytes (56 chars) on EVERY channel rather than raw bytes. QR libraries disagree on byte-mode across ecosystems and NDEF text records are simpler than custom MIME types. Costs 14 bytes, removes a whole class of cross-language bugs

- (decision) Nearby serviceId is constant echo.currency.v0; the framework tag lives in the endpoint name as <framework>:<deviceid>. Same-app mode filters on prefix, cross-framework mode accepts all. One boolean, client-side only, no re-advertising - that toggle IS the headline demo beat
